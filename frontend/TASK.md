# Техническое задание

## Описание
Это сайт одностраничный который будет использоваться для калькуляции
расходов на рекламу по выбранным фильтрам, чтобы клиент мог понять сколько ему будет стоить реклама.

Дизайн сделан в Figma, вот основной [фрейм](https://www.figma.com/design/TyvBpGsCycijVXeSVNrJSy/Workingdrops?node-id=12610-19358&t=7rflxRM0oIqq1Xw7-4)

Использовать Vite+React для реализации задачи.

Так как бэкенда еще нет, нужно придумать временный мок сервер который, отдает json данные на соответствующие запросы. 
Это может быть какой-то простой файл backend.ts или js. Однако мне нужно будет загрузить в конце результат на Vercel
поэтому нужно учесть чтобы это работало.

## Логика
Клиент получает прямую ссылку на страницу (например https://site.com/dvvt23fdf3f), в личных сообщениях или где ему 
сбрасывают. 
Он переходит, отображается id ордера и таймер – сколько этот ордер (соглашение) действует.
В момент загрузки страницы идет `fetch` запрос на бэкенд с id ордера `dvvt23fdf3f`, пока идет запрос показываем какую-то
анимацию загрузки. Когда сервер дает ответ, это json с нужными данными, которые включают в себя:
- **Срок годности ордера** - конечную дату, исходя из нее мы и показываем таймер обратного отсчета.
- **TDS** - количество кликов (не задумывайся что это, это просто число)
- **GSC** - количество кликов (не задумывайся что это, это просто число)
- **Цена** - в долларах, например 15000
- Данные для фильтров, а именно: 
    - Список 20 сайтов для Sites
    - Countries
    - Themes
    - Ads type

## Фильтры
Далее в дело вступает фильтрация фильтры, изменив которые пойдут повторные запросы для получения показателей TDS, GSC Цена.
Под надписями фильтров (Sites, Countries, Themes, Ads type) расположены кнопки соответствующих фильтров при клике на
которые выскакивает модалка.

За фильтрами, в том же рядке иконка вопросительного знака, если нажимает — то ниже фильтров блок сообщения, для 
понимания назовем его **Ads type settings**

### Блок **Ads type settings**

Он расположен под фильтрами и содержит в себе текст
"You can choose how the system should handle sites that match your country/themes but have all slots is selected Ads Type" 
и 3 радио-кнопки + кнопка Apply. При нажатии Apply сохраняем выбор в local storage чтобы в будущем при запросах к БД
прикреплять и этот выбор пользователя. 

Внизу этого блока сообщения расположен чекбокс **Always apply this choice automatically**, его логика такая, что если он
выбран то в localStorage сохраняем выбор из 3-х выбранных пунктов, если не выбран, то не сохраняем, и по дефолту ни один
вариант не активен. Как это выглядит можно глянуть на этом [скрине](https://www.figma.com/design/TyvBpGsCycijVXeSVNrJSy/Workingdrops?node-id=12659-2066&t=7rflxRM0oIqq1Xw7-4)

После нажатия кнопки Apply в блоке сообщения легкая анимация кнопки 
вызова – иконка вопросительного знака. Варианты анимации: 
- #fff без прозрачности
- #fff без прозрачности + scale 1.05-1.1

В самих модалках которые выскакивают при нажатии соответствующих кнопок, есть кнопки Reset to All sites и Apply,
при нажатии на которых происходит соответствующие действия и повторный запрос к серверу для актуализации данных 
TDS, GSC Цена.

### Фильтр Sites

Его дизайн [здесь](https://www.figma.com/design/TyvBpGsCycijVXeSVNrJSy/Workingdrops?node-id=12659-1524&t=7rflxRM0oIqq1Xw7-4).

В нем список сайтов на которых можно получить рекламу. Сайтов наверняка может быть много, поэтому закладывай что будет 
загрузка первых 20 которые мы получили еще при инициализации сайта в первом fetch, а затем инфинити скролл который
догружает по 20 сайтов с бэкенда.

Сверху расположен search c debounce, чтобы запрос шел раз в 300мс например.

Если пользователь выбрал несколько сайтов, то фильтра Countries и Themes становятся неактивными, 
а под ними выскакивает надпись **Country and Theme selection is disabled when specific sites are selected 
(sites-only mode).**, и кнопка **Got it** при клике на которую запоминаем в localStorage, то пользователь осведомлен
и больше не показываем эту надпись. Как это выглядит можно увидеть на этом 
[скрине](https://www.figma.com/design/TyvBpGsCycijVXeSVNrJSy/Workingdrops?node-id=12659-1442&t=7rflxRM0oIqq1Xw7-4)


### Фильтр Countries

Дизайн по аналогии Sites, но без search.

Список стран получен в первоначальном fetch-запросе.


### Фильтр Themes

Дизайн по аналогии Sites, но без search.

Список Themes получен в первоначальном fetch-запросе. В тестовые данные добавь пока вот такие темы

- Big Bass Splash
- Aviator
- Pin-UP
- можешь еще несколько придумать

### Фильтр Ads type

Дизайн модалки Ads type [здесь](https://www.figma.com/design/TyvBpGsCycijVXeSVNrJSy/Workingdrops?node-id=12692-309&t=7rflxRM0oIqq1Xw7-4)

Все варианты и категории вариантов получаем при первом fetch запросе. Верху расположен search который непонятно зачем
нужен, сделай его там просто чтобы был и без логики.

Если клиент выбирает такой тип рекламы, который уже занят на части сайтов, и при этом у нас нет записи про 
блок **Ads type settings**, какой вариант радио-кнопки пользователь там выбрал, то показываем принудительно ниже фильтров
блок **Ads type settings** с этими самыми радио-кнопками, который заставляет его выбрать. А после кнопки Apply
же делаем запрос на сервер за актуализацией данных (TDS, GSC Цена)

Если клиент выбирает тип рекламы, уже занятый на части сайтов, и при этом у нас сохранен его 
выбор «Показывать более дешевые рекламные слоты» (или только что выбрал это в блоке выше), то под основными 
фильтрами автоматически генерируются строки с этими альтернативными слотами. Так же выскакивает другой 
информативный блок с кнопочкой **Go It** при нажатии на которую запоминаем что пользователь ознакомлен и с этим и 
сохраняем это в localStorage, чтобы показывать снова.
