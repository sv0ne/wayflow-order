# wayflow-order page

Фронтенд на Vite + React + TypeScript. 

Реализован тестовый API сервер на Hono: он запускается локально как Node.js сервер.
Запускается отдельно из-под папки mock-server. Инструкции там.

## Локальная разработка

```sh
npm install
npm run dev
```

Команда запускает Vite. Страница доступна по адресу, который напечатает Vite.

## Логика работы

- При открытии страницы по ID заказа загружаются срок действия, метрики, Top Picks и начальные значения фильтров.
- Один запрос `GET /api/order` загружает данные заказа, метрики, Top Picks, страны и типы рекламы, первые 20 сайтов и полный список тем.
- Сайты загружаются страницами по 20 штук; поиск и выбранные страны передаются серверу. При смене страны клиент отдельно запрашивает обновлённые первые сайты и темы.
- Изменение фильтров отправляет запрос на пересчёт метрик и Top Picks. Если выбранный Ads Type содержит занятые слоты и правило ещё не выбрано, сервер возвращает `needsAdsTypeChoice: true`.
- Если выбран хотя бы один сайт, фильтры Countries и Themes блокируются и не учитываются.
- Когда для выбранных сайтов нет свободных слотов, API возвращает альтернативы.
- Иконка `?` рядом с фильтрами показывает правило обработки занятых слотов. Эта настройка сохраняется в `localStorage` и прикрепляется ко всем запросам `POST /api/metrics` и `GET /api/order`, чтобы сервер знал выбор пользователя.

### Сохраняем результат всплывающих подсказок localStorage
- Выбор правила обработки занятых слотов хранится в браузере в `localStorage` под ключом `adsTypeChoice` (`asc`, `desc` или `match`), и прикрепляется к запросам к серверу.
- При выборе фильтра по сайтам блокируются фильтры **Countries & Themes**, а пользователь получает всплывающее уведомление. Нажатие на кнопку **Got it** записывает флаг в `localStorage`, после чего подсказка больше не отображается.
- Если выбранная реклама недоступна на ряде выбранных сайтов, пользователю предлагаются альтернативные варианты и выводится информационное всплывающее уведомление. Нажатие на кнопку **Got it** сохраняет флаг в `localStorage`, после чего подсказка больше не отображается.

## API

- `GET /api/order?id=<order-id>` — заказ и все начальные данные интерфейса одним ответом.
- `GET /api/sites?search=<text>&offset=0&limit=20&country=<country>` — поиск и постраничная загрузка сайтов.
- `GET /api/filter-options?country=<country>` — темы и первые 20 сайтов для выбранной страны (параметр `country` можно передавать несколько раз). Без страны возвращает темы и сайты для всех стран.
- `POST /api/metrics` — пересчёт метрик, Top Picks и альтернатив по выбранным фильтрам.
- `DELETE /api/alternatives/:alternativeId?orderId=<order-id>&version=<version>` — удаление альтернативы с пересчётом данных заказа.

## Формат запросов и ответов

Все успешные ответы API возвращаются в JSON.

### `GET /api/order?id=<order-id>`

Параметр `id` — ID заказа. В ответе приходят данные заказа и начальное состояние страницы:

```json
{
  "id": "order-1234",
  "version": 1,
  "expiresAt": "2026-12-01T12:00:00.000Z",
  "stats": { "tds": 145100, "gsc": 125200, "price": 15000 },
  "topPicks": [{ "domain": "example.com", "theme": "Finance", "clicks": 1200 }],
  "filters": {
    "sites": ["site-1.example", "site-2.example"],
    "countries": ["US"],
    "themes": ["Finance"],
    "adTypes": [{ "category": "Banner", "options": [{ "id": "banner-1", "name": "Banner" }] }]
  }
}
```

`topPicks` — массив объектов `{ domain, theme, clicks }`. В `filters.adTypes` каждый элемент содержит `category` и массив `options` с полями `id` и `name`.

### `GET /api/sites?search=<text>&offset=0&limit=20&country=<country>`

Параметры `search`, `offset` и `limit` управляют поиском и постраничной загрузкой. `limit` не превышает 20. Параметр `country` можно повторять для нескольких стран; если он задан, список ограничивается доступными сайтами этих стран. Ответ содержит список сайтов и смещение следующей страницы; `nextOffset` равен `null`, когда страниц больше нет:

```json
{
  "items": ["example.com", "news.example"],
  "nextOffset": 20
}
```

### `GET /api/filter-options?country=<country>`

Возвращает доступные для выбранных стран темы и первые 20 сайтов. Параметр `country` можно повторять для нескольких стран. При смене страны клиент использует этот ответ, чтобы обновить зависимые фильтры. Пример:

```json
{
  "themes": ["Finance", "Sports"],
  "sites": ["example.com", "news.example"],
  "nextOffset": 20
}
```

В mock server нет настоящих связей сайта со страной: для демонстрации страна назначается сайту по его позиции в массиве сайтов, по кругу через список стран. Тема берётся из Top Picks для сайта, если она там задана; для остальных сайтов используется тема по позиции. В production API эти связи должны приходить из реальных данных бэкенда.

### `POST /api/metrics`

В теле запроса передаются выбранные фильтры — массивы ID или значений — и ID заказа. `adsTypeChoice` задаёт правило обработки занятых слотов: `asc`, `desc`, `match` или `null`.

Если среди `adTypes` есть слоты рекламы которые сейчас заняты на части сайтов, а `adsTypeChoice` равен `null` или отсутствует, сервер возвращает `needsAdsTypeChoice: true`. Клиент показывает `settings-card` блок пользователю, чтобы пользователь выбрал правило обработки. После выбора клиент повторяет запрос с заданным `adsTypeChoice`; сервер возвращает `needsAdsTypeChoice: false` и результат с альтернативами.

```json
{
  "orderId": "order-1234",
  "sites": ["example.com"],
  "countries": ["US"],
  "themes": ["Finance"],
  "adTypes": ["banner-1"],
  "adsTypeChoice": "asc"
}
```

Ответ содержит пересчитанные метрики и Top Picks, а также список альтернатив (может быть пустым):

```json
{
  "stats": { "tds": 139900, "gsc": 120700, "price": 14460 },
  "topPicks": [{ "domain": "example.com", "theme": "Finance", "clicks": 1100 }],
  "needsAdsTypeChoice": false,
  "alternatives": [{ "id": "alternative-1", "site": 3, "country": "US", "theme": "Finance", "adType": "Position 7-10" }],
  "version": 2
}
```

### `DELETE /api/alternatives/:alternativeId?orderId=<order-id>&version=<version>`

Удаляет альтернативу на сервере. `alternativeId` находится в пути, `orderId` и текущая версия заказа передаются в query-параметрах. Если строка альтернативы объединяет несколько сайтов, сервер удаляет всю группу. Фронтенд не вычитает метрики самостоятельно: он заменяет статистику, Top Picks, список альтернатив и версию данными ответа.

```json
{
  "stats": { "tds": 139900, "gsc": 120700, "price": 14460 },
  "topPicks": [{ "domain": "example.com", "theme": "Finance", "clicks": 1100 }],
  "alternatives": [],
  "version": 3
}
```

Если версия устарела или альтернатива не найдена, сервер отвечает JSON-ошибкой с HTTP `409` или `404` соответственно.

## Production-развёртывание

### Для backend-команды

Содержимое папки `dist/` можно разместить на сервере. Рядом с `index.html` создайте файл `config.js`:

```js
window.APP_CONFIG = {
  API_BASE_URL: 'http://site-api.me' // Адрес API
};
```
> **Важно для SPA-роутинга:**
> Так как это Single Page Application (React), все входящие запросы должны перенаправляться на главный файл index.html.

### Для frontend-команды

Если фронтенд собирается командой `npm run build` или публикуется на Vercel, адрес API можно задать через `VITE_API_BASE_URL` в `.env` либо в переменных окружения платформы:

```env
VITE_API_BASE_URL=https://site-api.me
```

`window.APP_CONFIG.API_BASE_URL` из `config.js` имеет приоритет. `VITE_API_BASE_URL` используется, только если `API_BASE_URL` не задан.
