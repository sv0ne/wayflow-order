# wayflow-order page

Фронтенд на Vite + React + TypeScript. 

Реализован тестовый API сервер на Hono: он запускается локально как Node.js сервер.
Запускается отдельно из-под папки mock-server. Инструкции там.

## Локальная разработка

```sh
npm install
npm run dev
```

Команда запускает Vite. Страница доступна по адресу, который напечатает Vite.

## Логика работы

- При открытии страницы по ID заказа загружаются срок действия, метрики, Top Picks и начальные значения фильтров.
- Изменение фильтров отправляет запрос на пересчёт метрик и Top Picks. Если выбранный Ads Type занят, сначала нужно выбрать правило обработки занятых слотов: добавить доступные типы по возрастанию или убыванию либо оставить только совпадения.
- Фильтр Sites: При начальной загрузке загружаются только список из 20 сайтов. При прокрутке внутри попапа, сайты дозагрузаются по 20 штук. Если выбран хотя бы один sites, фильтра Countries и Themes блокируются и не учитываются.
- Когда для выбранных сайтов нет свободных слотов, API возвращает альтернативы.
- Иконка "?" рядом с фильтрами показывает настройку обработки сайтов если все места заняты. Эта настройка сохраняется в `localStorage` и прикрепляется ко всем запросам `POST /api/metrics` и `GET /api/order`, что сервер знал выбор пользователя.

### Сохраняем результат всплывающих подсказок localStorage
- Выбор настройки обработки сайтов если все места заняты хранится в браузере в `localStorage` под ключом `adsTypeChoice` (`asc`, `desc` или `match`).
- При выборе фильтра по сайтам блокируются фильтры **Countries & Themes**, а пользователь получает всплывающее уведомление. Нажатие на кнопку **Got it** записывает флаг в `localStorage`, после чего подсказка больше не отображается.
- Если выбранная реклама недоступна на ряде выбранных сайтов, пользователю предлагаются альтернативные варианты и выводится информационное всплывающее уведомление. Нажатие на кнопку **Got it** сохраняет флаг в `localStorage`, после чего подсказка больше не отображается.

## API

- `GET /api/order?id=<order-id>` — срок действия, метрики, Top Picks и начальные параметры фильтров.
- `GET /api/sites?search=<text>&offset=0&limit=20` — поиск и постраничная загрузка сайтов.
- `POST /api/metrics` — пересчёт метрик и Top Picks по выбранным фильтрам.

## Формат запросов и ответов

Все успешные ответы API возвращаются в JSON.

### `GET /api/order?id=<order-id>`

Параметр `id` — ID заказа. В ответе приходят данные заказа и начальное состояние страницы:

```json
{
  "id": "order-1234",
  "expiresAt": "2026-12-01T12:00:00.000Z",
  "stats": { "tds": 145100, "gsc": 125200, "price": 15000 },
  "topPicks": [{ "domain": "example.com", "theme": "Finance", "clicks": 1200 }],
  "filters": {
    "sites": ["example.com"],
    "countries": ["US"],
    "themes": ["Finance"],
    "adTypes": [{ "category": "Banner", "options": [{ "id": "banner-1", "name": "Banner", "occupied": false }] }]
  }
}
```

`topPicks` — массив объектов `{ domain, theme, clicks }`. В `filters.adTypes` каждый элемент содержит `category` и массив `options` с полями `id`, `name` и `occupied`.

### `GET /api/sites?search=<text>&offset=0&limit=20`

Параметры `search`, `offset` и `limit` управляют поиском и постраничной загрузкой. `limit` не превышает 20. Ответ содержит список сайтов и смещение следующей страницы; `nextOffset` равен `null`, когда страниц больше нет:

```json
{
  "items": ["example.com", "news.example"],
  "nextOffset": 20
}
```

### `POST /api/metrics`

В теле запроса передаются выбранные фильтры — массивы ID или значений — и ID заказа. `adsTypeChoice` задаёт правило обработки занятых слотов: `asc`, `desc`, `match` или `null`.

```json
{
  "orderId": "order-1234",
  "sites": ["example.com"],
  "countries": ["US"],
  "themes": ["Finance"],
  "adTypes": ["banner-1"],
  "adsTypeChoice": "asc"
}
```

Ответ содержит пересчитанные метрики и Top Picks, а также список альтернатив (может быть пустым):

```json
{
  "stats": { "tds": 139900, "gsc": 120700, "price": 14460 },
  "topPicks": [{ "domain": "example.com", "theme": "Finance", "clicks": 1100 }],
  "alternatives": [{ "id": "alternative-1", "site": 3, "country": "US", "theme": "Finance", "adType": "Position 7-10" }]
}
```

## Production-развёртывание

### Для backend-команды

Содержимое папки `dist/` можно разместить на сервере. Рядом с `index.html` создайте файл `config.js`:

```js
window.APP_CONFIG = {
  API_BASE_URL: 'http://site-api.me' // Адрес API
};
```

### Для frontend-команды

Если фронтенд собирается командой `npm run build` или публикуется на Vercel, адрес API можно задать через `VITE_API_BASE_URL` в `.env` либо в переменных окружения платформы:

```env
VITE_API_BASE_URL=https://site-api.me
```

`window.APP_CONFIG.API_BASE_URL` из `config.js` имеет приоритет. `VITE_API_BASE_URL` используется, только если `API_BASE_URL` не задан.
